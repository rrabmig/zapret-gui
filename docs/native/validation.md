# Проверки нативной части

[Нативная часть](README.md) · [Документация](../README.md)

Все автоматические проверки выполняются на GitHub runners; [общие ограничения](../README.md#где-выполнять-проверки) действуют для всех разделов. Runner-проверки не подтверждают работоспособность обхода у провайдера.

## Ядро и контракт пакета

- Unit-тесты конфигурации, портов, списков, семантики IPSet, разделения оригиналов и рабочей копии.
- Проверки ZIP traversal, symlink, Windows-имён и дубликатов без учёта регистра.
- Тесты обновлений через loopback HTTP fixtures: SHA-256, размер, повторная установка, сетевые ошибки, отсутствие неявной активации.
- Проверки разбора аргументов: пробелы в путях, batch-переменные, shell-операторы, неизвестный формат.
- Идемпотентное обновление маркированного блока hosts и сохранение пользовательских строк.
- Чтение текста всех стратегий последней stable-сборки Flowseal. Текстовая проверка извлекает только `general*.bat`. Дополнительный `package-check` на Linux/Windows runners скачивает SHA-256-проверенный ZIP из релиза Flowseal через production Updater, устанавливает пакет во временный каталог, проверяет каталог версий, выбор и PrepareRuntime. Бинарники в этой проверке только копируются как файлы и никогда не запускаются.
- Core: каталог и числовой порядок версий, скрытые staging-каталоги, неполные релизы, выбор стратегии и сброс отсутствующих fake-файлов, запрет traversal/symlink при удалении, runtime отдельно от оригинала.
- Windows bridge (`go test -tags bindings .`): скачивание без активации, применение/откат/удаление, отсутствие запуска движка, все блокировки.

Эти проверки подтверждают работу загрузчика и контракта кода. Они не подтверждают реальную работу WinDivert, UAC, Windows-службы, системного WebView, конкретной стратегии или доступность сайтов.

## Ручная проверка на личном Windows

1. Открытие GUI не запускает winws, не создаёт службу и не отправляет сетевые запросы при выключенных проверках обновлений Flowseal и GUI.
2. Скачивание пакета из релиза Flowseal сохраняет текущий выбор. После отдельного применения версии GUI показывает её стратегии и .bin-файлы, но не запускает их.
3. При отказе UAC исходное окно остаётся открытым. При согласии открывается один повышенный экземпляр с теми же настройками.
4. Процесс запускается с выбранной стратегией, корректными путями с пробелами и настройками фильтров. Ошибка WinDivert видна в журнале.
5. «Остановить» завершает свой процесс. Сторонний winws и чужие службы не завершаются.
6. Служба устанавливается в ProgramData с защищённым ACL, запускается, работает после закрытия GUI и после перезагрузки, останавливается и удаляется из GUI после UAC.
7. Обновление/откат сборки Flowseal и смена списков блокируются при действующем процессе, установленной службе и открытых оригинальных инструментах.
8. Смена версии сохраняет пользовательские списки и дополнительные IP. Ошибка загрузки сохраняет активный пакет.
9. Оригинальные Standard tests и DPI checkers доступны, используют выбранную рабочую копию; завершённый сеанс освобождает блокировку. При ограничении PowerShell policy GUI её не меняет автоматически.
10. Hosts обновляется после предпросмотра, создаёт backup, повторное применение не дублирует блок и сохраняет сторонние строки.
11. Кэш Discord переименовывается только после закрытия Discord. Резервные папки можно вернуть вручную, когда Discord закрыт.
12. Светлая/тёмная тема, клавиатура, ошибки, длительное скачивание, отсутствие сети и GitHub rate limit понятны пользователю.

На Linux/macOS проверяются окно и работа с пакетами/списками; запуск zapret из Windows-сборки должен оставаться недоступным.

## Регрессия загрузки официального ZIP

Загрузка Flowseal 1.10.4 ошибочно требовала `LICENSE.txt`, отсутствующий в release ZIP. Регрессионные инертные фикстуры не содержат этого файла; целостность ZIP и обязательные файлы для работы продолжают проверяться. CI дополнительно проходит production-путь на настоящем upstream ZIP на Linux и Windows.

## Каталоги приложения

Windows использует GUIForZapret для установки, AppData и защищённой копии службы в ProgramData; WebView2 находится внутри каталога данных. Переноса прежних каталогов нет по решению автора: старые каталоги автоматически не удаляются. Схема и стабильные системные ID описаны в [архитектуре](architecture.md).

Проверки установки, удаления, метаданных и GUI updater — в [distribution](../distribution/validation.md). Проверки клавиатуры, тем, переводов и инертного bridge — во [frontend](../frontend/testing.md).
