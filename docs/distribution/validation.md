# Проверки дистрибуции

[Дистрибуция](README.md) · [Обновление GUI](gui-updates.md) · [Документация](../README.md)

Сборки и автоматические проверки выполняются на GitHub runners; см. [общие ограничения](../README.md#где-выполнять-проверки). Проверки ядра и интерфейса описаны отдельно в [native](../native/validation.md) и [frontend](../frontend/testing.md).

## Сборки и установщик

Сборка GUI для трёх ОС. Для генератора Wails bindings есть отдельная точка входа без конфигурации, блокировки, журнала и создания движка. Окно приложения, движок, драйвер и сетевые пробы в CI не запускаются; отдельные проверки Setup и инертной SCM fixture описаны в этом документе.

`scripts/check-windows-installer.ps1`: silent install, метаданные обоих EXE, Publisher в HKCU, ярлык «Пуск», обновление/переустановка с сохранением sentinel-данных и удаление. Проверка mutex не запускает GUI; проверка SCM регистрирует временную инертную тестовую службу с cmd.exe, никогда её не запускает и удаляет в finally. Никаких winws/драйверов/DPI checkers.

На личном Windows дополнительно проверить интерактивный установщик, отказ UAC при удалении службы через GUI, флажки полной очистки, кириллицу/пробелы в пути и отказ установки WebView2. Runner-проверки не подтверждают реальную работу обхода.

Windows VERSIONINFO содержит явные таблицы `0409` (English) и `0419` (Russian), включая CompanyName и версии файла/продукта. Проверка читает метаданные уже установленного EXE и Setup через Windows FileVersionInfo, а не только JSON-конфиг.

## Кодировка и параметры Setup

- Русские строки Setup были UTF-8 без BOM и читались компилятором NSIS как ANSI, несмотря на `Unicode true` в выходном EXE. `project.nsi` теперь UTF-8 с BOM; сохранять эту кодировку при редактировании.
- Вопрос о ярлыке перенесён из MessageBox во время копирования в отдельную страницу с необязательным флажком. `scripts/check-installer-dialogs.ps1` открывает только собранный Setup на Windows runner с `/LANG=1033` и `/LANG=1049`, доходит до страницы параметров, проверяет фактический текст флажка и его выключенное состояние, затем завершает свой процесс Setup. Установка/GUI/движок в этой проверке не запускаются. Обычный silent install/upgrade/uninstall smoke остаётся отдельным шагом.

## Название, метаданные и каталоги

Проверять новое название окна, HTML title, GUI/Setup ProductName, DisplayName установленного приложения, новый EXE и ярлык. macOS-пакет называется `GUI for zapret.app`, CFBundleName — GUI for zapret, исполняемый файл — GUIforzapret. Windows smoke проверяет замену только прежнего EXE/ярлыка с сохранением sentinel-версий и настроек; системные ID `ZapretDesktop` остаются стабильными. Upstream winws/WinDivert не переименовываются.

Windows smoke проверяет default install root `%LocalAppData%\Programs\GUIForZapret`, установку, обновление, удаление и сохранность данных в новых каталогах. AppData/ProgramData также называются GUIForZapret, WebView2 находится внутри каталога данных. Миграции прежних каталогов нет; старые каталоги автоматически не удаляются.

## Обновление GUI

На runners: SemVer/downgrade, draft/prerelease и чужие asset URL, отсутствующий/неверный digest, ETag/304, 404, rate limit, испорченное/прерванное/слишком длинное скачивание, повторная проверка кэша, отмена/частичная ошибка Setup с восстановлением старого EXE, ошибка перезапуска, сохранение versions/data. Установщики в этих unit-тестах инертные; настоящий Setup проверяется отдельно существующим native installer job. UI проверяет раздельные download/apply, отмену подтверждения и доступность.

На личном Windows после публикации двух разных стабильных версий: нормальное обновление и перезапуск, закрытие GUI с запущенной службой, отмена Setup, блокировка обновления при повышенных правах/оригинальных утилитах, сохранение списков/версий/службы, ошибка сети и ручное восстановление. Корпоративный компьютер для этого не использовать. Подпись и SmartScreen реальными тестами runners не подтверждаются.

Наличие publisher/CompanyName в метаданных не является доверенной подписью. Успешные проверки runners не подтверждают отсутствие предупреждений SmartScreen и реальную работу обхода.
