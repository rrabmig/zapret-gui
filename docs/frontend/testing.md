# Проверки интерфейса

[Фронтенд](README.md) · [Документация](../README.md)

На корпоративной машине не запускать сборку, приложение, тесты или dev-server. Локальный Storybook с инертным мостом запускается только по отдельному явному запросу пользователя. Все следующие команды предназначены для GitHub runner либо другого разрешённого устройства:

```sh
cd frontend
npm ci --ignore-scripts
npm run build
npm run build-storybook
npm run build:fixtures
npx playwright install --with-deps chromium
npm run test:ui
```

Playwright проверяет визуальные состояния и разделы, взаимодействие через mock Bridge, ошибки, production без моста, каждую story, RU/EN, сохранение языка и черновиков, сообщения, управление версиями Flowseal и подтверждение обновления GUI. Сценарии выполняются в светлой и тёмной теме; дополнительно проверяется окно шириной 760px.

Эталоны лежат рядом с владельцами: `frontend/src/screens/AppShell/test/__screenshots__/{light,dark}` и `frontend/src/screens/Updates/test/__screenshots__/{light,dark}`. Playwright сравнивает изображения, а не просто сохраняет новые; допустимое отличие — 0.2% пикселей. В CI загружается `frontend-review` с HTML-отчётом, traces при ошибках, PNG и статическим Storybook. Скачанный каталог Storybook можно открыть через HTTP-сервер на разрешённом устройстве.

Для намеренного обновления дизайна запустить **Build desktop → Run workflow** на ветке PR с `update_visual_baselines: true`. Скачать `frontend-review`, просмотреть PNG из всех `src/**/test/__screenshots__`, перенести их в репозиторий и закоммитить. Обычный PR-run не обновляет эталоны. Desktop-сборки Windows/macOS/Linux выполняются параллельно проверкам. Создание draft release требует успеха всех jobs. Автоматического merge нет.

Chromium и инертный мост не подтверждают работу WinDivert, UAC, Windows-службы и системного WebView. Реальный запуск проверяется отдельно на личном Windows-устройстве.

## Accessibility и клавиатура в Storybook

- **Accessibility** (`@storybook/addon-a11y`): в нижней панели нажать **Run accessibility scan** для axe-аудита текущей story. Анализ ограничен `#storybook-root`; автоматический запуск при переключении stories выключен, проверки запускаются по команде. В панели доступны найденные проблемы и подсветка элементов, в toolbar — симуляция особенностей зрения.
- **Pseudo States** (`storybook-addon-pseudo-states`): в toolbar можно включить `hover`, `focus`, `focus-visible`, `active` и другие CSS-состояния. У Button есть отдельные stories Hover и KeyboardFocus. Это визуализация CSS, а не перемещение настоящего клавиатурного фокуса.
- Штатные горячие клавиши Storybook включены. `Ctrl/Cmd+K` — поиск компонента; `Alt+←/→` — предыдущая/следующая story; `Alt+↑/↓` — компонент; `1`, `2`, `3` — фокус на дереве, preview и панели; `F6` / `Shift+F6` — переход между областями; `Alt+A` — показать/скрыть панель; `Alt+F` — полный экран. Комбинации можно менять в **Settings → Keyboard shortcuts** (`Ctrl/Cmd+Shift+,`).
- Внутри preview работают нативные `Tab`, `Shift+Tab`, `Enter`, `Space`, стрелки для select/radio и `Escape` для диалога. Для просторного просмотра доступен **Open in isolation mode**.

Оба addon — только devDependencies. Они не входят в production-бандл и не подключаются к Go.

## Клавиатура и доступность самого приложения

`Tab` и `Shift+Tab` проходят по нативным кнопкам и полям, `Enter`/`Space` активируют кнопки. В навигации разделов стрелки и Home/End переводят фокус и открывают раздел; в меню файлов стрелки перемещают фокус, а Enter/Space открывают файл, сохраняя подтверждение несохранённых изменений. Первая ссылка «Перейти к содержимому» позволяет пропустить боковую панель. У активного раздела есть `aria-current`, у полей — связанные подписи, у диалога — фокус на отмене и возврат при Escape.

В CI `@axe-core/playwright` проверяет реальные экраны приложения в обеих темах (WCAG 2 A/AA, 2.1 A/AA, 2.2 AA), включая имена элементов управления и контраст. Это дополнение к настоящим клавиатурным действиям в сквозном сценарии; автоматический axe-аудит не заменяет ручную проверку скринридером.

## Проверки ссылок и нативных полей

Sidebar содержит описание со ссылкой на Flowseal и три project links столбиком. UI-тест проверяет href, порядок, отступы, делегирование клика в Wails BrowserOpenURL, hover-эталон, оформленный native select в раскрытом состоянии и клавиатурный выбор.

Для сборок Flowseal проверяются отдельные скачивание, применение, откат, удаление, отмена подтверждения, открытие папки как вызов bridge и блокировки. Для обновления GUI — отдельные скачивание и установка, отмена подтверждения перезапуска. Все эти действия используют инертный bridge.

В UI должны различаться GUI rrabmig, zapret bol-van и пакеты Flowseal. Название окна и HTML title — GUI for zapret; кнопки управления процессом и службой относятся к отдельно скачанному zapret.

Проверки самого установщика и обновления GUI описаны в [distribution](../distribution/validation.md), реальное поведение движка — в [native](../native/validation.md).
