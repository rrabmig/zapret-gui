# Граница проверки

На корпоративной машине разработки **не запускать приложение, winws, service.bat, тесты стратегий, DPI checkers, установку WinDivert, службы или изменения сети**. По запросу пользователя локально также не выполняются компиляция, unit-тесты и GUI-проверки. Разрешённая подготовка исходников ограничивается чтением документации, редактированием, форматированием и загрузкой зависимостей.

## Что делает GitHub Actions

- Unit-тесты конфигурации, портов, списков, семантики IPSet, разделения оригиналов и рабочей копии.
- Проверки ZIP traversal, symlink, Windows-имён и дубликатов без учёта регистра.
- Тесты обновлений через loopback HTTP fixtures: SHA-256, размер, повторная установка, сетевые ошибки, отсутствие неявной активации.
- Проверки разбора аргументов: пробелы в путях, batch-переменные, shell-операторы, неизвестный формат.
- Идемпотентное обновление маркированного блока hosts и сохранение пользовательских строк.
- Чтение текста всех стратегий последней stable-сборки Flowseal. Текстовая проверка извлекает только `general*.bat`. Дополнительный `package-check` на Linux/Windows runners скачивает SHA-256-проверенный ZIP из релиза Flowseal через production Updater, устанавливает пакет во временный каталог, проверяет каталог версий, выбор и PrepareRuntime. Бинарники в этой проверке только копируются как файлы и никогда не запускаются.
- Сборка GUI для трёх ОС. Для генератора Wails bindings есть отдельная точка входа без конфигурации, блокировки, журнала и создания движка. Окно приложения, движок, драйвер и сетевые пробы в CI не запускаются; отдельные проверки Setup и инертной SCM fixture описаны ниже.
- Проверка интерфейса в Chromium с неисполняемой заглушкой Go-моста: opt-in, подтверждение сетевых проверок, блокировка на время оригинальных утилит, поиск стратегий, списки и недоступность zapret из Windows-сборки на других ОС. Playwright сравнивает скриншоты всех разделов и состояний в обеих темах с эталонами, дополнительно проверяет узкое окно 760px и каждую story. Артефакт `frontend-review` содержит отчёт, скриншоты и Storybook; это данные фикстуры, а не результат запуска WinDivert.

TypeScript, production-сборка Vite, бюджет JS+CSS 100 KiB gzip и Storybook проверяются независимо от desktop-сборок; draft release требует успеха всех jobs. Playwright-сценарии выполняются в каждой теме. Обновление эталонов возможно отдельным ручным запуском workflow и требует коммита PNG после просмотра.

Эти проверки подтверждают работу загрузчика и контракта кода. Они не подтверждают работоспособность WinDivert, UAC, Windows-службы, WebView/UI, конкретной стратегии или доступность сайтов у провайдера.

## Отдельная ручная проверка на личном Windows-устройстве

1. Открытие GUI не запускает winws, не создаёт службу и не отправляет сетевые запросы при выключенном AutoCheck.
2. Скачивание пакета из релиза Flowseal сохраняет текущий выбор. После отдельного применения версии GUI показывает её стратегии и .bin-файлы, но не запускает их.
3. При отказе UAC исходное окно остаётся открытым. При согласии открывается один повышенный экземпляр с теми же настройками.
4. Процесс запускается с выбранной стратегией, корректными путями с пробелами и настройками фильтров. Ошибка WinDivert видна в журнале.
5. «Остановить» завершает свой процесс. Сторонний winws и чужие службы не завершаются.
6. Служба устанавливается в ProgramData с защищённым ACL, запускается, работает после закрытия GUI и после перезагрузки, останавливается и удаляется из GUI после UAC.
7. Обновление/откат/смена списков блокируются при действующем процессе, установленной службе и открытых оригинальных инструментах.
8. Смена версии сохраняет пользовательские списки и дополнительные IP. Ошибка загрузки сохраняет активный пакет.
9. Оригинальные Standard tests и DPI checkers доступны, используют выбранную рабочую копию; завершённый сеанс освобождает блокировку. При ограничении PowerShell policy GUI её не меняет автоматически.
10. Hosts обновляется после предпросмотра, создаёт backup, повторное применение не дублирует блок и сохраняет сторонние строки.
11. Кэш Discord переименовывается только после закрытия Discord. Резервные папки можно вернуть вручную, когда Discord закрыт.
12. Светлая/тёмная тема, клавиатура, ошибки, длительное скачивание, отсутствие сети и GitHub rate limit понятны пользователю.

На Linux/macOS проверяются окно и работа с пакетами/списками; запуск zapret из Windows-сборки должен оставаться недоступным.

## Дополнительные проверки версий и установщика на runner

- Core: каталог и числовой порядок версий, скрытые staging-каталоги, неполные релизы, выбор стратегии и сброс отсутствующих fake-файлов, запрет traversal/symlink при удалении, runtime отдельно от оригинала.
- Windows bridge (`go test -tags bindings .`): скачивание без активации, применение/откат/удаление, отсутствие запуска движка, все блокировки.
- Playwright с инертным bridge: отдельные скачивание/выбор/откат/удаление, отмена подтверждения, открытие папки как вызов bridge, блокировки.
- `scripts/check-windows-installer.ps1`: silent install, метаданные обоих EXE, Publisher в HKCU, ярлык «Пуск», обновление/переустановка с сохранением sentinel-данных и удаление. Проверка mutex не запускает GUI; проверка SCM регистрирует временную инертную тестовую службу с cmd.exe, никогда её не запускает и удаляет в finally. Никаких winws/драйверов/DPI checkers.

На личном Windows дополнительно проверить интерактивный установщик, отказ UAC при удалении службы через GUI, флажки полной очистки, кириллицу/пробелы в пути и отказ установки WebView2. Runner-проверки не подтверждают реальную работу обхода.

Windows VERSIONINFO содержит явные таблицы `0409` (English) и `0419` (Russian), включая CompanyName и версии файла/продукта. Проверка читает метаданные уже установленного EXE и Setup через Windows FileVersionInfo, а не только JSON-конфиг.


## Регрессии с личного Windows (05.11)

- Загрузка Flowseal 1.10.4 ошибочно требовала `LICENSE.txt`, отсутствующий в release ZIP. Регрессионные инертные фикстуры не содержат этого файла; целостность ZIP и обязательные файлы для работы продолжают проверяться. CI дополнительно проходит production-путь на настоящем upstream ZIP на Linux и Windows.
- Русские строки Setup были UTF-8 без BOM и читались компилятором NSIS как ANSI, несмотря на `Unicode true` в выходном EXE. `project.nsi` теперь UTF-8 с BOM; сохранять эту кодировку при редактировании.
- Вопрос о ярлыке перенесён из MessageBox во время копирования в отдельную страницу с необязательным флажком. `scripts/check-installer-dialogs.ps1` открывает только собранный Setup на Windows runner с `/LANG=1033` и `/LANG=1049`, доходит до страницы параметров, проверяет фактический текст флажка и его выключенное состояние, затем завершает свой процесс Setup. Установка/GUI/движок в этой проверке не запускаются. Обычный silent install/upgrade/uninstall smoke остаётся отдельным шагом.


## Ребрендинг GUI for zapret (05.11)

Проверять новое название окна, HTML title, GUI/Setup ProductName, DisplayName установленного приложения, новый EXE и ярлык. macOS-пакет называется `GUI for zapret.app`, CFBundleName — GUI for zapret, исполняемый файл — GUIforzapret. Windows smoke проверяет замену только прежнего EXE/ярлыка с сохранением sentinel-версий и настроек; системные ID `ZapretDesktop` остаются стабильными. Upstream winws/WinDivert не переименовываются.

В UI разделены GUI rrabmig, zapret bol-van и сборки Flowseal. Проверка обновлений относится к пакету Flowseal, а новый Setup GUI пока устанавливается вручную. PR #4 пользователь влил, но его исправления на личном Windows пока не проверял; runner-проверки не выдавать за пользовательское подтверждение.


## Небольшой редизайн и GUIForZapret (05.11)

Удалена надпись «Рабочее пространство» и текстовые подписи авторов; sidebar содержит описание со ссылкой на Flowseal и три project links столбиком. Новый UI-тест проверяет href/порядок/паддинги, делегирование пользовательских кликов в Wails BrowserOpenURL, hover-эталон, оформленный native select в раскрытом состоянии и клавиатурный выбор. Обычные тесты форм/языков/версий остаются.

Windows smoke проверяет новый default install root GUIForZapret, установку/обновление/удаление и сохранность данных уже внутри новых каталогов. AppData/ProgramData также называются GUIForZapret, WebView2 находится внутри нового каталога данных. Переноса прежних каталогов нет по явному решению пользователя: он единственный пользователь и предпочёл не добавлять миграции. Старые каталоги автоматически не удаляются.
