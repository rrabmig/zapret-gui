# Проект автообновления GUI через GitHub Releases

Это предложение следующего этапа, не реализованный updater. Пользователь планирует открыть rrabmig/zapret-gui; поэтому целевая дистрибуция — публичные Releases без токенов и входа пользователя. Пока репозиторий private, анонимный updater не сможет получить его releases.

## Поведение

1. Независимая opt-in настройка проверки обновлений GUI при открытии. Проверка только получает метаданные `/repos/rrabmig/zapret-gui/releases/latest`, с кэшированием ETag и backoff для rate limit/ошибок сети. Официальные пакеты Flowseal обновляются отдельно.
2. Сравнение строгих SemVer GUI; стабильный канал исключает draft и prerelease. Несовместимая ОС/архитектура, downgrade и неизвестная схема manifest блокируются. В UI — новая версия, заметки релиза, размер, «Скачать» и «Позже».
3. Загрузка точного asset Setup во временный каталог, проверка размера и SHA-256. ZIP для другой ОС не запускается как Windows-установщик. Только разрешённые HTTPS-хосты GitHub и release-assets. Прерванное скачивание не меняет установку.
4. Перед применением отдельное подтверждение «Обновить и перезапустить». При открытых оригинальных утилитах требуется завершить их сеанс; управляемый дочерний процесс останавливается штатно. Служба использует защищённую копию ProgramData и не должна переустанавливаться автоматически ради смены GUI.
5. GUI освобождает mutex и завершается; отдельный небольшой updater-helper ждёт завершения PID, запускает проверенный Setup в per-user режиме, проверяет результат и предлагает повторный запуск GUI. Настройки и `versions` сохраняются. Повторный запуск не включает движок.
6. Пока нельзя достоверно проверить свежий Setup/подпись, предлагать открыть официальный релиз. Не отключать SmartScreen/Defender и не устанавливать сертификаты в доверенные хранилища.

## Доверие к обновлению

GitHub digest и публикуемый `SHA256SUMS` обнаруживают повреждение доставки, но компрометация GitHub-аккаунта может заменить и бинарник, и checksum. Для unattended-установки нужен подписанный manifest (версия, платформа, архитектура, имя/размер/SHA-256 asset, схема) с публичным ключом в GUI и приватным ключом только в защищённом signing job. Ротация ключа — явная часть протокола. Authenticode — отдельная подпись GUI/Setup для Windows; она не подменяется полем Publisher.

Текущий pipeline уже выдаёт стабильное имя `ZapretDesktop-Setup-<MAJOR.MINOR.PATCH>-x64.exe`, встроенные метаданные версии и `SHA256SUMS` в draft release. Перед включением автообновления нужны тегированные опубликованные releases, источник доверенной подписи и Windows-проверки отказов: GUI не завершился, Setup вернул ошибку, файл занят, недостаточно места, отмена, повторная попытка и восстановление предыдущего GUI. Откат GUI не должен переключать движок.
