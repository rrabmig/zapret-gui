# Обновление GUI через GitHub Releases

Версия GUI for zapret и версия Windows-пакета Flowseal независимы. Этот updater получает **только GUI** из `rrabmig/zapret-gui`, не устанавливает драйверы и не меняет службу или выбранную сборку Flowseal.

## Использование

В разделе «Сборки Flowseal» отдельный блок **GUI for zapret**:

1. «Проверить обновление GUI» получает метаданные последнего стабильного опубликованного релиза. Отдельный opt-in переключатель включает проверку при открытии; он не скачивает и не устанавливает файлы. По умолчанию выключен.
2. «Скачать обновление GUI» на Windows x64 получает только точный `GUIforzapret-Setup-MAJOR.MINOR.PATCH-x64.exe`. Проверяются HTTPS, репозиторий и путь, размер (до 128 MiB), GitHub SHA-256 digest. Повреждённое или неполное скачивание удаляется, действующая установка сохраняется.
3. «Обновить и перезапустить» требует отдельного подтверждения. Сначала сохраните правки. Оригинальные утилиты должны быть закрыты, состояние процессов — доступно. Откройте GUI **без прав администратора**: per-user Setup и помощник не повышают права.
4. GUI останавливает только собственный дочерний процесс zapret. Его служба продолжает работать из защищённой копии `%ProgramData%\GUIForZapret`.
5. Копия текущего GUI запускается как помощник из каталога данных `gui-updates/download-*`. Этот режим обрабатывается до создания Wails, mutex, журнала и движка. Помощник открывает handle текущего GUI, подтверждает готовность и ждёт его выхода до 60 секунд; чужие процессы не завершает.
6. После повторной проверки SHA-256 помощник сохраняет прежний EXE и запускает **обычный видимый Setup** в текущую папку установки, с выбранным языком. Пользователь может отменить Setup. После успеха перезапускается GUI с прежним `--data-dir`; движок автоматически не запускается.

На macOS/Linux доступна проверка и ссылка на релиз, установка вручную. Старые версии без updater нужно один раз обновить вручную.

## Ошибки и ограничения

- Строгие теги `vMAJOR.MINOR.PATCH`, сравнение числовых компонентов; draft, prerelease, downgrade, неизвестная локальная версия и невалидный asset не устанавливаются. Собственная CI-версия `MAJOR.MINOR.PATCH-<8 hex>` может обновиться до стабильной версии с тем же номером.
- Нет опубликованных релизов (HTTP 404) — обычное состояние «Опубликованных релизов пока нет». Репозиторий публичный, токен в приложение не встраивается.
- ETag повторно использует проверенные метаданные; проверки ограничены одной в минуту. HTTP 403/429 включает минимум 15 минут backoff с учётом `X-RateLimit-Reset`. Неудачный запрос не удаляет ранее скачанный проверенный установщик.
- Таймаут выхода, ошибка запуска Setup или его ненулевой exit code не перезапускают новый GUI. При ошибке/отмене Setup восстанавливается прежний **EXE GUI**. Это не полный транзакционный откат вспомогательных документов или регистрации NSIS: они могли обновиться. Пакеты, списки, настройки и служба не откатываются и не удаляются.
- При ошибке остаются Setup, резервный EXE и файл `helper-*.exe.json.failed`; сообщение помощника на RU/EN показывает путь диагностики. Если восстановить EXE мешает блокировка, сообщение/файл указывает путь backup. Закройте собственные окна GUI и повторите ручную установку из Releases. После успешного обновления Setup и backup удаляются; работающий helper EXE остаётся в кэше до ручной очистки.
- SmartScreen/Defender и системные политики не отключаются. Установщик пока **без доверенной Authenticode-подписи**. HTTPS и digest GitHub обнаруживают повреждение доставки, но не защищают от захвата GitHub-аккаунта или замены release самим издателем. Поэтому загрузка и обычная видимая установка требуют действий пользователя; полностью фоновая установка не реализована. Для неё отдельным этапом нужен подписанный manifest с ключом доверия в GUI, ротацией и защищённым signing job. Authenticode остаётся отдельной задачей.

## Публикация версии

1. Влить проверенный PR. Каждый следующий релиз обязан иметь **больший** номер (например, после `v0.2.0` — `v0.2.1`). Одно и то же `0.1.0` больше не использовать для всех версий.
2. Создать и отправить тег `vMAJOR.MINOR.PATCH` на выбранный коммит main. Workflow проверяет GUI/ядро, собирает три платформы, проверяет Windows Setup и создаёт **draft release** с Setup EXE, ZIP macOS/Linux и `SHA256SUMS`.
3. Проверить результат Actions и заметки draft, затем **Publish release** в GitHub Releases. Не помечать стабильную версию prerelease. Только опубликованный публичный release доступен updater без входа в GitHub; Actions artifacts и draft releases источником обновления не являются.
4. Проверить скачивание/установку на личном Windows. Первая установка версии с updater — вручную; следующий опубликованный больший тег проверяет весь цикл.

API-контракт: [GitHub Releases](https://docs.github.com/en/rest/releases/releases), [GitHub asset digests](https://github.blog/changelog/2025-06-03-releases-now-expose-digests-for-release-assets/). Параметр NSIS `/D=` передаётся последним без кавычек согласно [документации NSIS](https://nsis.sourceforge.io/Docs/Chapter3.html).
