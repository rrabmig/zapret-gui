# Архитектура GUI for zapret

## Два варианта поддержки ОС

| | GUI для zapret со сборками Flowseal — выбран | Единый GUI с отдельными движками |
|---|---|---|
| Windows | zapret из сборки Flowseal + WinDivert | То же |
| Linux | GUI, настройки, пакеты | Дополнительный движок и адаптер firewall/служб |
| macOS | GUI, настройки, пакеты | Дополнительный ограниченный движок; неполный паритет |
| Репозиторий Flowseal | Не изменяется | Может не изменяться, но уже недостаточен как единственный upstream |
| Стратегии | Все стратегии из ZIP из релиза Flowseal | Отдельные платформенные стратегии |
| Сопровождение | GUI, загрузчик пакетов и небольшой контракт аргументов | GUI, пакеты, привилегированные адаптеры, сетевые правила и их очистка |
| Новая функция upstream | Доступна в оригинальном меню сразу | Нужна оценка и реализация для каждой платформы |

Выбор пользователя: первый вариант. Поэтому приложение честно показывает недоступность zapret из Windows-сборки на Linux/macOS. Оно не пытается эмулировать WinDivert и не использует неподтверждённые порты стратегий.

Ограничение обусловлено исходной сборкой: [Flowseal README](https://github.com/Flowseal/zapret-discord-youtube#readme), [обсуждение macOS у автора zapret2](https://github.com/bol-van/zapret2/discussions/157). Старый zapret поддерживал на macOS ограниченный вариант tpws; это не эквивалент UDP/WinDivert-возможностей Flowseal. Для нативных Linux/macOS-портов нужен отдельный проектный этап и отдельная проверка поведения.

## Обновления: fetch, встраивание или releases

| Способ | Преимущества | Обязательства |
|---|---|---|
| `git fetch` / clone upstream | Можно получить каждое изменение `main` | Git на машине пользователя, изменяемая ветка, неполные изменения между релизами, нет единого проверяемого пакета |
| Vendoring / submodule / `go:embed` движка | Полностью автономный первый запуск | Каждое обновление требует сборки GUI; в репозиторий и дистрибутив попадают Windows-бинарники и их лицензии; submodule пользователю всё равно нужно получать |
| **Отдельные официальные releases** | **Не зависит от сборки GUI и Git; полный пакет, checksum, версии и откат** | Нужен загрузчик и проверка небольшого контракта запуска |

Выбраны отдельные releases. Проверка обновлений здесь относится к последней стабильной сборке Flowseal по команде или при открытии GUI, если включена настройка. Сам GUI обновляется независимо из `rrabmig/zapret-gui/releases/latest`: отдельная opt-in проверка, проверенный Windows Setup и установка с подтверждением через помощник вне каталога установки. На macOS/Linux — ручная установка из релиза. См. [gui-updates.md](gui-updates.md). Это не синхронизация каждого коммита `main` и не безусловное обновление работающего драйвера.

## Границы компонентов

```text
Wails window + React/TypeScript + CSS Modules (Vite dist)
          │ allowlisted Go methods
          ▼
App: settings, lifecycle, interlocks, versions storage, selection/rollback pointer
   ├── core.Updater ── HTTPS ── official GitHub Releases
   ├── core.StrategyArgs ── read general*.bat as text
   ├── core.PrepareRuntime ── pristine package + persistent overrides
   └── core.Engine
        ├── Windows: child process, SCM, UAC, original upstream tools
        └── Other: explicit unsupported state, no shell fallback
```

В GUI нет открытого локального HTTP API, командной строки, принимающей произвольные команды, и внешних ресурсов интерфейса. Wails использует системный WebView. Редактируемые пользовательские значения валидируются и передаются движку отдельными аргументами.

## Контракт стратегий

GUI находит `general*.bat` динамически и читает аргументы `winws.exe`. Известные переменные: `%BIN%`, `%LISTS%`, `%GameFilter%`, `%GameFilterTCP%`, `%GameFilterUDP%`. Batch-файл при обычном запуске не исполняется; служебные побочные действия `service.bat` не выполняются.

Незнакомая переменная, несколько команд движка, незакрытые кавычки или shell-операторы означают несовместимую стратегию. GUI не пытается угадать новую семантику. Стратегия отмечается как недоступная для прямого запуска, а оригинальное меню остаётся доступным. Это локализует сопровождение формата в `internal/core/strategy.go`.

Именно поэтому полное меню upstream не переписывается в Go. Для удобства наиболее частые действия реализованы напрямую, а редкие команды и новые пункты открываются оригинальной утилитой. Правки в её исходники не вносятся.

## Жизненный цикл

- При открытии нет движка, драйвера, службы, сетевых проб или запросов обновлений, если их проверка не была включена ранее.
- Переключатель разрешения запуска лишь открывает соответствующие действия. Сам ничего не запускает.
- Перезапуск с UAC сохраняет каталог данных и ждёт освобождения блокировки предыдущего экземпляра.
- Дочерний процесс останавливается при нормальном закрытии GUI; отдельная служба продолжает работать. После аварийного завершения GUI оставшийся движок определяется как внешний и автоматически не завершается.
- Перед сменой пакета, фильтров, списков или стратегии GUI требует остановить процессы и удалить службу. Путь службы указывает в отдельную защищённую копию, а не в пользовательский AppData.
- При открытии оригинальных утилит GUI блокирует изменение рабочего дерева до явного завершения сеанса. Это защищает от удаления файлов, которыми пользуются внешние процессы.
- Все запускающие или системные действия централизованно проверяют `EngineAllowed`; остановка своего процесса доступна всегда. Обновления данных и загрузка пакетов не запускают движок.

## Оформление

Интерфейс использует общие токены цвета, типографики, радиусов и отступов, светлую/тёмную/системную тему и CSS Modules. Боковая навигация отделена от рабочих разделов; обзор выделяет состояние движка и ручной запуск. В production нет Storybook, фикстур, внешних шрифтов или веб-ресурсов.

При обновлении дизайна использованы рекомендации [Stageshow](https://github.com/benjitaylor/skills/tree/main/stageshow) по визуальной иерархии, плотности, отступам и нейтральным поверхностям. Его демонстрационный kit и постановочные анимации не включаются в рабочее приложение; компоненты реализованы для настоящего ввода, клавиатуры и Go-моста. Подробности: [frontend.md](frontend.md).

## Хранилище версий и установка

`App` получает раздельные `root` (настройки/списки/runtime) и `versionsDir` (полные релизы). В Windows `versionsDir` определяется от фактического EXE независимо от cwd и `--data-dir`; на macOS/Linux — `<root>/versions`, вне app bundle. `Updater.Install` принимает непосредственно каталог версий; staging и публикация rename остаются на одном томе. Поддержки/миграции прежнего `packages` нет.

`SelectVersion` вычисляет предложение конфигурации без записи и запуска, проверяет полноту релиза и совместимость стратегии. Каталог отдаёт это предложение UI; при смене недоступной стратегии требуется подтверждение. `download-version` сохраняет active/previous; `activate` атомарно сохраняет новый выбор. Все изменения версий используют существующие interlocks. Активную версию удалить нельзя, удаление previous сбрасывает указатель отката.

NSIS устанавливает GUI per-user, используя стабильный ключ `rrabmig.ZapretDesktop`. Скрипт установки и ресурс `info.json` принадлежат репозиторию; Wails генерирует только остальные build assets. Обновление перезаписывает файлы GUI, а не дерево `versions`. Uninstaller проверяет mutex и установленную службу, сохраняет данные по умолчанию и никогда рекурсивно не удаляет корень установки.


## Название и границы авторства

GUI for zapret — самостоятельный интерфейс rrabmig. zapret — отдельный проект bol-van; Windows-сборки и стратегии поставляет Flowseal; WinDivert — отдельный драйвер. Пользовательские строки, заголовки, EXE, bundle и Setup обозначают GUI for zapret. Версии пакетов в UI называются сборками Flowseal, а запуск и автозапуск относятся к zapret.

Каталоги приложения, данных и защищённой копии службы называются `GUIForZapret`; перенос из прежних каталогов не выполняется. Технические ID `ZapretDesktop` в SCM, mutex, регистрации и маркерах hosts остаются стабильными. Они не используются как пользовательский бренд. Upstream-бинарники и их метаданные не переименовываются.
